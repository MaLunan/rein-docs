## 开发哲学(贯穿所有阶段)

1. **每阶段可独立验证**:每个阶段都有明确「验收标准」,跑通了才进下一阶段。
2. **为后续留形状,但不提前实现**:典型如 M0 —— Session 设计成可序列化、Loop 写成单步推进(为 M2 的 resume 留形状),但 M0 不实现 resume。区分「设计成可扩展」与「现在就实现」,避免返工也避免过度设计。
3. **先做后说、即时验证**:每写完一块代码立刻跑测试/示例核实,只认事实回执,不靠记忆。
4. **极薄优先**:能不进核心的就走 extras;能用一种机制的不引入三种。

## 阶段依赖关系

```
        ┌──────────────► M1 多厂商打磨
        │
M0 最小闭环 ──┼──────────────► M3 上下文+可观测
        │
        ├──► M2 恢复机制 ──► M4 扩展层
        │
        └──────────────► M5 脚手架
```
